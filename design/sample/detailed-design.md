# 詳細設計書 — sample-web（Agent2 動作確認用サンプル）

> 意図的に不足項目を含みます。初回実行では「差戻し（BLOCKED）」になるのが正しい挙動です。

## 1. デプロイ先

| 項目 | 値 |
|---|---|
| サブスクリプションID | 00000000-0000-0000-0000-000000000000 |
| デプロイスコープ | リソースグループ |
| リソースグループ名 | rg-sample-web-dev |
| リージョン | 東日本 |

## 2. リソース一覧

| No | リソース種別 | リソース名 | SKU / プラン | 備考 |
|---|---|---|---|---|
| 1 | App Service プラン | asp-sample-web-dev | Premium v3 P1v3 | OS: Linux |
| 2 | Web アプリ | app-sample-web-dev | （No.1 のプランを使用） | ランタイムは別途決定 |
| 3 | ストレージアカウント | stsamplewebdev001 | Standard / LRS | 種類: StorageV2 |
| 4 | 仮想ネットワーク | vnet-sample-web-dev | — | アドレス空間 10.10.0.0/16 |
| 5 | プライベートエンドポイント | pe-stsamplewebdev001-blob | — | No.3 の blob 用 |

## 3. ネットワーク

- サブネット `snet-app`（10.10.1.0/24）: Web アプリの VNet 統合に使用する。
- ストレージアカウントへのアクセスはプライベートエンドポイント経由のみとし、パブリックネットワークアクセスは無効とする。
- プライベート DNS ゾーン `privatelink.blob.core.windows.net` を作成し、No.4 の VNet にリンクする。

## 4. セキュリティ

- Web アプリは HTTPS のみ許可し、最小 TLS バージョンは 1.2 とする。
- ストレージアカウントの最小 TLS バージョンは 1.2、BLOB の匿名アクセスは無効とする。
- Web アプリはシステム割り当てマネージド ID を有効にする。

## 5. RBAC

| 対象（プリンシパル） | ロール | スコープ |
|---|---|---|

| 運用チーム（Entra ID グループ、オブジェクトID: 未定） | 閲覧者 | リソースグループ |
